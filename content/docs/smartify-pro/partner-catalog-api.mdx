title: "Partner Catalog API"
description: "Read the Smartify catalog and submit your own products for Smartify review, using a partner API key."
---

The catalog endpoints are part of the [Partner API](/docs/smartify-pro/partner-api) and use the same keys, base URL, errors and rate limit. There are two separate things you can do:

- **Read the Smartify catalog** (`catalog:read`), once Smartify enables it for your organization.
- **Submit your own products** (`catalog:submit`) to add to, change or remove from the Smartify Pro catalog. Smartify reviews every submission.

<Callout type="warn">
The old `sk_live_pcat_` catalog keys and the `/api/partner-catalog/products` endpoints are retired and answer `410 Gone`. Create a partner API key in **Settings → Integrations** with the `catalog:submit` scope and use the endpoints below.
</Callout>

## Authentication

Use a partner API key as a Bearer token. Do not send `X-API-Key`.

```http
Authorization: Bearer spk_live_…
```

Base URL:

```text
https://api.pro.smartify.in/v1
```

## Read the Smartify catalog

```http
GET /catalog/products
```

Needs the `catalog:read` scope, and the partner catalog must be enabled for your organization by Smartify. Otherwise the answer is `403 feature_not_enabled`.

Optional query: `search` (up to 120 characters), matched against the SKU and name.

```bash
curl -s -H "Authorization: Bearer $SMARTIFY_API_KEY" \
  "https://api.pro.smartify.in/v1/catalog/products?search=switch"
```

The response is `{ "data": [product, …] }`. Each product has `sku`, `name`, `gst_rate`, `stock_quantity`, `image_url`, `hsn` and `updated_at`.

## Submit your own products

Submissions go through Smartify review. Nothing is published until Smartify approves it.

### Who can submit

- Smartify has approved catalog access for your organization. Until then, submission endpoints answer `403 catalog_not_enabled`.
- Your organization is eligible: a paid-active partner, or an approved co-branded partner.
- The key has the `catalog:submit` scope.

### How it works

1. Submit a create, update or delete request with your key. The answer is always `202 Accepted`.
2. The request is stored with status **PENDING**.
3. A Smartify admin **approves** or **rejects** it.
4. Only approved requests change the Pro catalog.

Submitting again for the same `partner_sku` replaces the earlier submission record for that SKU with the new one, which goes back to PENDING.

### Endpoints

| Request | What it does |
|---|---|
| `POST /catalog/submissions` | Submit a new product. |
| `PUT /catalog/submissions/{sku}` | Submit a change to one of your products. |
| `DELETE /catalog/submissions/{sku}` | Ask to remove one of your products. |
| `GET /catalog/submissions` | List your submissions. Optional query: `status=PENDING`, `APPROVED` or `REJECTED`. |

`{sku}` is your own SKU, the `partner_sku`. Smartify upper-cases it and replaces spaces with hyphens.

### Create

The product goes in a `product` object next to your `partner_sku`.

```bash
curl -s -X POST https://api.pro.smartify.in/v1/catalog/submissions \
  -H "Authorization: Bearer $SMARTIFY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "partner_sku": "SMARTIFY-4GSS-001",
    "product": {
      "name": "4 Gang Scene Switch",
      "brand": "Smartify",
      "category": ["Switches"],
      "protocol": ["Zigbee 3.0"],
      "technology": ["Wireless"],
      "pricing": { "mrp": 4999, "selling_price": 4599 }
    }
  }'
```

### Update

```bash
curl -s -X PUT https://api.pro.smartify.in/v1/catalog/submissions/SMARTIFY-4GSS-001 \
  -H "Authorization: Bearer $SMARTIFY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product": {
      "name": "4 Gang Scene Switch (Rev B)",
      "brand": "Smartify",
      "category": ["Switches"],
      "protocol": ["Zigbee 3.0"],
      "technology": ["Wireless"],
      "pricing": { "mrp": 5199, "selling_price": 4799 }
    }
  }'
```

### Delete

```bash
curl -s -X DELETE https://api.pro.smartify.in/v1/catalog/submissions/SMARTIFY-4GSS-001 \
  -H "Authorization: Bearer $SMARTIFY_API_KEY"
```

### List your submissions

```bash
curl -s -H "Authorization: Bearer $SMARTIFY_API_KEY" \
  "https://api.pro.smartify.in/v1/catalog/submissions?status=PENDING"
```

The response is `{ "data": [submission, …] }`, newest first.

## Product fields

Send these in the `product` object. Only `name` is required; everything else has a default.

| Field | Notes |
|---|---|
| `name` | Required, up to 300 characters. |
| `brand` | Up to 160 characters. Defaults to `Partner`. |
| `description` | Up to 5000 characters. |
| `category` | List of category names. Defaults to `["Partner Products"]`. |
| `protocol` | List of protocols. Defaults to `["N/A"]`. |
| `technology` | List of technologies. Defaults to `["Wireless"]`. |
| `hero_image` | Image URL, up to 2048 characters. |
| `images` | List of image URLs. Defaults to the hero image. |
| `enabled` | `false` to submit the product as disabled. Defaults to `true`. |
| `pricing.mrp` | Maximum retail price. Defaults to the selling price, or 0. |
| `pricing.selling_price` | Defaults to the MRP. |
| `pricing.dealer_price` | Optional. |
| `gst_rate` | One of `0`, `5`, `12`, `18`, `28`. Anything else is refused. |
| `hsn_code` | Digits only, as a string. |

A list field also accepts a comma-separated string. A bad value answers `400 invalid_parameter` with `detail` saying what to fix; a body that is not JSON answers `400 invalid_json`.

## The submission record

Create, update and delete return the submission as `{ "data": { … } }`. It includes:

| Field | Meaning |
|---|---|
| `partner_sku` and `catalog_sku` | Your SKU, and the SKU the product gets in the Pro catalog if approved. |
| `operation` | `CREATE`, `UPDATE` or `DELETE`. |
| `status` | `PENDING`, `APPROVED` or `REJECTED`. |
| `submitted_at` and `submitted_by` | When it was submitted, and by which key. |
| `reviewed_at`, `reviewed_by`, `review_reason` | Filled in once Smartify has reviewed it. |

## Review process

- **PENDING**: your request is received and waiting for Smartify review. Nothing is visible in the catalog or inventory yet.
- **APPROVED**: the create, update or delete is applied in the Pro catalog. The product records where it came from: `source = PARTNER`, your organization and your `partner_sku`.
- **REJECTED**: the catalog is unchanged. A reason may be stored in `review_reason` (for example missing required fields, invalid price data, or a duplicate or mismatched SKU).

Check progress with `GET /catalog/submissions`.
