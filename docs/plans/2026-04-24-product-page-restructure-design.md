# Product Page Restructure Design

**Date:** 2026-04-24
**Status:** Approved
**Primary audience:** System integrators / installers

---

## Problem

Current product pages generated by `generate_docs.py` have poor structure for installers:

1. Critical warnings (`Important`) and requirements (`Requires`) are buried at the bottom as plain blockquotes
2. "Technical Overview" mixes prose with a redundant "Key Specifications" bullet list that duplicates the Specifications table
3. Marketing "Overview" section is noise for installers
4. No installation/wiring steps on individual product pages — only on category index
5. "Pricing" is a vague section name for procurement info that includes GST + HSN

---

## New Page Structure

Every product page will follow this order:

```
[hero image]
Protocol · Type · SRP  ·  Works with badges

<Callout type="warn">  [limitations]  </Callout>   ← above the fold, visible immediately
<Callout type="info">  [dependencies] </Callout>

## Description
[technical prose only — Key Specifications bullet list stripped]

## Specifications
[structured table — unchanged]

## Installation
[category-level install guide — makes each page self-contained]

## Ordering
[SRP / GST rate / HSN code]
```

---

## Changes to `generate_docs.py`

### 1. `product_page(p, category_slug)` — new signature
Add `category_slug: str` parameter.

### 2. Frontmatter description
Use first line of `desc_technical` (not `desc_consumer` tagline).
Reason: technical description is more useful for SEO and installers searching for specs.

### 3. Callouts at the top
Replace blockquotes with `<Callout>` JSX components, moved above all `##` sections:
```mdx
<Callout type="warn">For loads above 4A use external SSR or contactor.</Callout>
<Callout type="info">Requires: Zigbee coordinator or hub</Callout>
```
Only rendered if `limitations` / `dependencies` fields are non-empty.

### 4. Remove "Overview" section
Drop the consumer/marketing description section entirely.
Installers don't need taglines.

### 5. "Technical Overview" → "Description", strip embedded spec list
Rename section to `## Description`.
Strip the embedded "Key Specifications" bullet list from `desc_technical` by splitting at the first `\nKey Specifications` or `\n⚠` occurrence and using only the prose part.

### 6. Add `## Installation` section
Include `INSTALL_GUIDES[category_slug]` content on every product page.
Keeps each page self-contained — installers don't need to navigate to the category index.

### 7. "Pricing" → "Ordering"
Rename section header only. Table contents unchanged (SRP / GST / HSN).

### 8. `main()` — pass `slug` to `product_page()`
```python
write_file(cat_dir / f"{p_slug}.mdx", product_page(p, slug))
```

---

## What Does NOT Change

- Category index pages (`category_index()` function) — keep product listing + install guide
- Specs table structure and field mapping
- Hero image, quick-info line, Works With badges
- `meta.json` files and sidebar structure
- `mdx-components.tsx` — already includes `defaultComponents` from `fumadocs-ui/mdx` which provides `<Callout>`
- All other files outside `generate_docs.py`

   - A sensor page (e.g. `/docs/sensors/zigbee-contact-sensor`) — placement guide in Installation section

4. Verify no products with empty `limitations`/`dependencies` show empty Callout blocks
